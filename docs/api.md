# API

`log-server`'s HTTP API. All request/response bodies are JSON. Interactive
docs (Swagger UI / ReDoc) are also auto-generated by FastAPI at `/docs` and
`/redoc` on a running instance.

This covers only log-sump's own built-in routes. A given deployment may
mount additional routes via `create_app()`'s `extra_routers` seam (see
[Architecture → Extension model](architecture.md#extension-model)) — check
`/docs` on the running instance for the full, deployment-specific route
list.

Base URL in the default single-container deployment: `http://<host>:8080`
(`server.bind_port` in config, default `8080`).

## Authentication

Send an API key on every authenticated request as the `X-API-Key` header:

```
X-API-Key: <your-api-key>
```

Keys are provisioned directly in Redis (not through this API) as a set of
permitted `docker_host` values under `logsump:auth:{sha256(api_key)}` — see
[Architecture → Auth model](architecture.md#auth-model). There are two
authorization tiers:

- **Daemon-scoped** — `/catalog` and `/records` require the key to be
  permitted for the specific `docker_host` being accessed.
- **Any valid key** — `/admin/redis/command` only requires a *known* key;
  it isn't scoped to a daemon (see that endpoint's own section for why).

Missing/unknown key → `401 Unauthorized`. Valid key, wrong daemon →
`403 Forbidden`.

`/health/*` endpoints require no authentication.

---

## `GET /health/live`

Liveness — always `200` if the process is responding at all. No auth
required.

**Response**
```json
{"status": "ok"}
```

## `GET /health/ready`

Readiness — additionally pings Redis. No auth required.

**Response** (`200`)
```json
{"status": "ok"}
```

**Response** (`503`, Redis unreachable)
```json
{"status": "redis unreachable"}
```

---

## `GET /catalog`

The daemons this `log-sump` instance watches, filtered to the ones the
caller's API key is permitted to see.

**Auth**: daemon-scoped (returns only permitted entries; no error if some
configured daemons are filtered out).

**Response** — `200`, array of:

| Field | Type | Meaning |
|---|---|---|
| `id` | string | daemon identifier |
| `host` | string | configured host |
| `enabled` | bool | whether `log-listener` is actively watching it |

```json
[
  {"id": "prod-a", "host": "10.0.0.5", "enabled": true}
]
```

---

## `GET /records`

Logs and/or metrics for one daemon, over a time range, kind-filtered,
paginated, interleaved by `ts` when both kinds are requested. Daemon-level
(`__system__`) metrics are just regular metric records — pass
`container_id=__system__` like any other filter.

**Auth**: daemon-scoped to `docker_host`.

**Query parameters**

| Name | Type | Default | Notes |
|---|---|---|---|
| `docker_host` | string | *required* | must be permitted for the caller's key |
| `kind` | `log` \| `metric` \| `both` | `both` | |
| `container_id` | string | — | exact match, post-filter |
| `level` | string | — | log-only, exact match, post-filter |
| `q` | string | — | log-only, case-insensitive substring match on `message` |
| `start` | ISO 8601 datetime | now − 1h | inclusive |
| `end` | ISO 8601 datetime | now | inclusive |
| `log_cursor` | string | — | resume a previous `/records` page's log stream |
| `metric_cursor` | string | — | resume a previous `/records` page's metric stream |
| `limit` | int | `server.page_size_default` (200) | clamped to `server.page_size_max` (1000); applies **per kind**, not to the combined response — see below |

**Pagination**: `log` and `metric` streams are paginated **independently**,
each with its own cursor, rather than one combined cursor over a merged
list. `limit` is a per-kind fetch cap, so a `kind=both` page can return up
to `2 * limit` records — this keeps each kind's cursor advancing exactly
past what was actually fetched for that kind, with no risk of skipping or
duplicating entries across pages. `next_log_cursor`/`next_metric_cursor`
come back `null` once that kind's stream has nothing left in the requested
time range; pass the non-null one(s) back as `log_cursor`/`metric_cursor`
to get the next page.

**Response** — `200`

```json
{
  "records": [
    {
      "kind": "log",
      "docker_host": "prod-a",
      "container_name": "web-1",
      "container_id": "a1b2c3d4e5f6",
      "ts": "2026-08-14T12:00:00.196657Z",
      "seq": 1,
      "stream": "stdout",
      "level": "info",
      "message": "hello world",
      "fields": {},
      "raw": "2026-08-14T12:00:00.196657372Z hello world"
    },
    {
      "kind": "metric",
      "docker_host": "prod-a",
      "container_name": "web-1",
      "container_id": "a1b2c3d4e5f6",
      "ts": "2026-08-14T12:00:03Z",
      "seq": 1,
      "metric_scope": "container",
      "cpu_pct": 0.58,
      "mem_used_bytes": 17658020,
      "mem_limit_bytes": 8320425394,
      "mem_pct": 0.21,
      "net_rx_bytes": 1950,
      "net_tx_bytes": 126,
      "blk_read_bytes": 9040000,
      "blk_write_bytes": 0,
      "pids": 6,
      "system": null,
      "source": "docker stats",
      "raw": { "...": "original docker stats JSON row" }
    }

  "next_metric_cursor": null
}
```

## `POST /admin/redis/command`

Read-only Redis inspection: run one allowlisted command directly against
the Redis store — e.g. to check what's actually in a stream without going
through `/records`. See
[Architecture → Auth model](architecture.md#auth-model) for why this is
scoped by *command*, not by *credential tier*.

**Auth**: any valid API key (not daemon-scoped).

**Request body**

| Field | Type | Notes |
|---|---|---|
| `command` | string | case-insensitive; must be in the allowlist below |
| `args` | array of strings | passed through to Redis positionally |

**Allowed commands** (`log_sump.server.redis_inspect`):

```
GET MGET EXISTS TYPE TTL PTTL STRLEN KEYS SCAN DBSIZE
HGET HMGET HGETALL HKEYS HVALS HLEN HEXISTS
SMEMBERS SCARD SISMEMBER
LRANGE LLEN LINDEX
ZRANGE ZSCORE ZCARD ZRANK
XRANGE XREVRANGE XLEN XINFO
PING INFO MEMORY
```

Anything else → `403 Forbidden`.

**Response** — `200`
```json
{"result": ["<stream-id>", {"data": "<record JSON>"}]}
```

`result`'s shape mirrors whatever that Redis command normally returns
(binary strings decoded to UTF-8, lists/tuples/dicts recursively).

**Example**

```bash
curl -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"command": "XRANGE", "args": ["logsump:stream:prod-a:log", "-", "+"]}' \
  http://localhost:8080/admin/redis/command
```

## Errors

FastAPI's default error shape:

```json
{"detail": "invalid API key"}
```

| Status | Meaning |
|---|---|
| `401` | missing or unknown API key |
| `403` | key valid, but not permitted for the requested daemon; or a disallowed Redis command |
| `422` | request validation failure (e.g. `kind` not one of `log`/`metric`/`both`) |
